Procedural Galaxy Generator

A galaxy, its star systems, their planets and the terrain on those planets — all derived from one 48-bit seed, all explorable in a browser tab.

The idea

Most procedural generators store what they made. This one stores nothing. Every structure in the universe — galaxy morphology, each star's spectral class, each planet's atmosphere, the mountains on a given patch of one planet's surface — is a pure function of a seed chain. That single decision is what makes the rest of the design possible:

  • The URL is the save file. #seed=7F8A-2C91-BD44&view=planet&star=118427&planet=2 restores the exact view on any machine.
  • Detail can be thrown away without consequence, because anything evicted can be rebuilt from its seed. That's what lets the level-of-detail system be aggressive.
  • Bugs are reproducible. A seed is a bug report.

Seed chain: root = hash(code) → galaxy → sector:sx:sy → star i → planet j → tile:lat:lon. String labels for structural nodes; allocation-free integer mixing for the 250,000-star hot path.

Architecture

Twenty-five namespaced modules, concatenated into one HTML file by a 90-line build script. The important boundary is that generation never touches the DOM or three.js — which is exactly what lets the same generation code run inside a Web Worker. 

src/core/    rng, noise, seed, perf          determinism + instrumentation
src/gen/     galaxy, star, planet, system,
             sector, factions, economy       pure generation — no DOM, no three.js
src/render/  stage, orbit, galaxyView, systemView,
             planetView, planetTexture, surfaceView
                                             one renderer, four swappable views
src/ui/      dom, hud, controls, inspector, devpanel
src/app.js                                   state, navigation, URL hash

Six decisions worth talking about

1. The Web Worker has no source file

Instead of maintaining a separate worker script that would inevitably drift from the main thread's copy, the worker bundle is assembled at runtime from the same function objects the main thread uses, via Function.prototype.toString(). One implementation, two threads, no possibility of divergence. If workers are unavailable it falls back to synchronous generation and says so in the dev panel.

2. Sub-pixel dimming in the star shader

Below one pixel, a point sprite physically cannot get smaller — so naive distance attenuation makes a more distant galaxy look brighter, because every star is clamped up to a full pixel. The fix is to clamp the size and fold the lost area into intensity, so total emitted light falls off correctly.

3. Picking one star out of 250,000 in about 2 ms

No raycaster and no octree. The position buffer is projected with the view-projection matrix in a flat typed-array loop and the nearest screen-space hit wins. A spatial tree would have to be rebuilt on every regeneration; a linear pass over contiguous memory does not, and it is fast enough that the difference is invisible.

4. Sea level from a histogram, not a guess

Planet elevation is noise, so "sea level = 0.5" gives a planet whose stated water coverage is a lie. Instead the generator bins elevation into a 256-bucket histogram and solves for the threshold that yields the target coverage — a world that says 71% water really has 71% of its surface under water.

5. Planet classes come from physics, not a dice roll

Equilibrium temperature is computed as T = 278.6 · L^¼ · a^-½ · (1 − albedo)^¼, plus a greenhouse term. Class follows from temperature, mass and water. The payoff is that the universe stays internally consistent — no ocean worlds at 900 K, no ice giants hugging their star.

6. Two levels of detail, not one

LOD 0 is the entire galaxy as a single point cloud — one draw call, 14 bytes per star. LOD 1 is per-sector detail, streamed on demand into an LRU cache and evicted freely. Eviction is safe precisely because every node is a pure function of its seed: the cache can never be the only copy of anything.

Measured cost

Chrome on an M-series laptop, 220,000 stars:

  • Galaxy generation ~120 ms (in the worker, off the main thread)
  • Spatial index ~4 ms · faction Voronoi ~20 ms · sector detail ~2 ms
  • Star system build ~0.3 ms · star pick ~2 ms
  • 512² planet texture bake ~300 ms (behind a loader — still on the main thread, and the next thing I'd move)
  • One draw call for the galaxy, at 60 fps

How I know it works

node test/verify.mjs drives headless Chromium through the whole product: boot cleanliness, seed determinism (same seed → bit-identical star buffer; different seed → different; and the worker path matching the main-thread path bit for bit), the full galaxy → system → planet → surface path via real mouse events, all five morphologies, and deep-link restoration. It also reads back the framebuffer per view, so a silently black render fails the build instead of shipping.

Five bugs that taught me something

  1. A race I created myself. location.replace() fires hashchange on a later task, so my setTimeout(0) guard lost the race and every navigation regenerated the entire galaxy. Fixed by comparing the written hash by value instead of trying to out-time the event loop.
  2. Frame-delta clamping ate slow frames. Genuinely slow frames were being reset to 16 ms, so camera tweens never reached their targets on software renderers. Now: over 1 s means the tab came back (ignore it), over 100 ms means cap it.
  3. A cache that only filled by accident. After regeneration the sector cache stayed empty until the camera happened to cross a sector boundary. Regeneration now re-streams explicitly.
  4. A classification hole. A temperate world with 45% surface water was classed rocky and rendered bone-dry. Added a humid class for wet worlds with unbreathable air.
  5. A scoring bug that flattered bad planets. Habitability scored 67% for a dry world with breathable air. Water is now a gate, not a bonus.

What I'd do next

  • Move planet texture baking into the worker, removing the last main-thread block.
  • Generate the galaxy progressively in chunks so a million stars streams in rather than blocking.
  • A screen-space bloom pass, and ring shadows on gas giants.
  • Port the shell to TypeScript + Vite, keeping gen/ as a framework-free package.
